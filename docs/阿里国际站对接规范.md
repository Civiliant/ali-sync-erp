# 阿里国际站（Alibaba.com）对接规范

> 版本：v1.0　|　状态：核心接口已核实，OAuth/网关地址待开放平台控制台最终确认
> 依据：官方接口列表（ICBU－交易）核实结果 + 开放平台文档

## 1. 对接范围与凭证

- 平台：阿里巴巴国际站（Alibaba.com，ICBU）
- 认证：OAuth 2.0，需**企业账号**申请"跨境数据应用"，部分接口需**权限包审批**
- 凭证：`appKey` + `appSecret`（开放平台控制台获取）；调用时携带 `access_token`（即 SDK 的 `sessionKey`）
- 调用方式：TOP 协议（`method` 参数指定 API 名，公共参数 + 业务参数）

## 2. OAuth 授权流程（已核实官方文档）

### 2.1 授权入口地址（正式环境）
- 获取授权码：`https://oauth.alibaba.com/authorize`
- 换取/刷新 token：`https://oauth.alibaba.com/token`

### 2.2 授权 URL（Server-side flow）
```
https://oauth.alibaba.com/authorize?response_type=code&client_id={app_key}&redirect_uri={redirect_uri}&state={state}&view=web&sp=icbu
```
> ⚠️ **关键**：`sp=icbu` 是国际站（ICBU）标识，**必须携带**，否则可能授权到错误平台。

### 2.3 换取 access_token
```
POST https://oauth.alibaba.com/token
grant_type=authorization_code, code, client_id, client_secret, redirect_uri
```

### 2.4 刷新 token
```
POST https://oauth.alibaba.com/token
grant_type=refresh_token, refresh_token, client_id, client_secret
```
> ⚠️ **每次刷新后 refresh_token 作废**，必须用返回的最新 refresh_token 覆盖。

### 2.5 token 响应字段
`access_token` / `refresh_token` / `expires_in`(86400=24h) / `re_expires_in` / `r1_expires_in` / `r2_expires_in` / `w1_expires_in` / `w2_expires_in` / `taobao_user_id` / `taobao_user_nick` / `sub_taobao_user_id` / `sub_taobao_user_nick`

### 2.6 授权流程步骤
```
前端【添加店铺】
   → 生成授权地址（client_id + redirect_uri + state + view=web + sp=icbu）
   → 浏览器跳转官方授权页，用户登录并授权
   → 回调带 code + state
   → 后端校验 state（Redis，600s，用后即删）
   → POST 用 code 换 access_token + refresh_token
   → taobao_user_id → stores.account_id；sub_taobao_user_id → platform_accounts
   → AES-256-GCM 加密 token 入库
   → 定时任务刷新 token（每天扫，7 天内到期即刷新）
```

## 4. 订单列表接口 `alibaba.seller.order.list`（已核实）

### 4.1 请求参数（`param_trade_ecology_order_list_query`）

| 参数 | 必须 | 说明 |
|------|------|------|
| `role` | ✅ 必须 | `seller` / `buyer`，取订单用 `seller` |
| `create_date_start` / `create_date_end` | 可选 | 创建时间区间（美国时间） |
| `modified_date_start` / `modified_date_end` | 可选 | **修改时间区间（美国时间）→ 增量同步游标** |
| `status` | 可选 | 订单状态筛选 |
| `page_size` | 可选 | 每页数量，**最大 100** |
| `start_page` | 可选 | 起始页，**从 0 开始** |
| `other_login_id` | 可选 | 买家登录账号 |
| `sales_man_login_id` | 可选 | 业务员登录账号 |

### 4.2 响应（关键字段）

```
result.success            // 是否成功
result.error_code / error_message
result.value.order_list[].trade_id    // 订单号（幂等键）
result.value.order_list[].create_date // 创建时间
result.value.order_list[].modify_date // 修改时间
result.value.total_count              // 总记录数
```

### 4.3 异常格式（TOP 统一）

```json
{ "code": 50, "msg": "Remote service error",
  "sub_code": "isv.invalid-parameter", "sub_msg": "非法参数" }
```

## 5. 增量同步策略

```
1. 游标 = 上次成功同步的 modified_date（美国时间，转 UTC 存储）
2. 调 alibaba.seller.order.list：
     modified_date_start = 游标 - 5分钟重叠(防边界漏单)
     modified_date_end   = 当前时间
     role = seller, page_size = 100, start_page = 0
3. 分页循环拉取，直到 total_count 或空页
4. 以 (store_id, platform_order_id=trade_id) UPSERT 幂等入库
5. 更新游标，写 sync_jobs / sync_job_items
6. 失败经 BullMQ 重试，超限告警
```

- **时区注意**：平台时间是**美国时间**，入库存 UTC（`TIMESTAMPTZ`），展示转本地时区。
- **频次**：按开放平台配额，默认建议 5–10 分钟轮询一次，用增量拉取避免触限。

## 6. 订单状态映射

| 平台状态 | 含义 | ERP 内部状态 |
|---------|------|-------------|
| `unpay` / `paying` | 待付/支付中 | `pending` |
| `paid` / `relating` / `captured` | 已付款/请款完成 | `paid` |
| `undeliver` | 待卖家发货 | `ready_to_ship` |
| `delivering` / `wait_confirm_receipt` | 发货中/待收货 | `shipped` |
| `trade_success` | 交易成功 | `completed` |
| `trade_close` | 交易关闭 | `cancelled` |
| `charge_back` | 拒付 | `refunded` |
| `frozen` | 冻结 | `frozen` |

> 建议：`orders` 表存两个状态——`platform_status`（平台原始状态）+ `order_status`（ERP 业务流转状态：待处理→已采购→已发货→已完成→退款）。

## 7. 安全要求（硬约束）

1. `app_secret`、`access_token`、`refresh_token` 用独立 `APP_ENCRYPTION_KEY`（AES-256-GCM）加密存储。
2. 禁止在日志、接口响应、异常信息中输出任何 token/密钥明文。
3. `state` 随机生成、Redis 600s、用后即删，防 CSRF/重放。
4. `redirect_uri` 必须与开放平台后台配置完全一致。
5. token 刷新失败标记 `REFRESH_FAILED`，禁止无限重试。
